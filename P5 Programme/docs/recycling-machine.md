# Recycling machines in Workshop and City

Recycling is an editable Workshop workspace. Its starter has a City intake Feeder, a photo Model watching a track, item-linked routing filters and a Gate, and cardboard, metal, plastic and human-check Bins. Model training and the model library open from the Model controls. Bin destination controls support cardboard, glass, metal, paper, plastic, trash and human check independently of the child's display name.

**Save sorter** first saves and flushes the editable machine. It then validates and atomically replaces `projects.recyclingMachine`. A failed draft save, validation or project transaction leaves the previous published machine in place. **Try in AI City** invokes the same operation. Switching Workshop tabs saves the outgoing workspace; a failed save prevents navigation. Empty workspaces also get saved slots.

The version 1 snapshot contains the source machine ID, name, seed, authored table, compiled intake ID, compiled Bin ID-to-material bindings, an internal revision and signatures. The snapshot uses the Workshop private-data projection. A session-only learning dependency is an explicit publication refusal; its private examples cannot be copied into the snapshot. Public model weights and available learned banks travel with the graph. An older sorter model can be placed through the photo Model's controls when it retains public library provenance. Older records remain in the project even when they need reteaching.

`workshop/logic/recycling-machine.js` uses the editor's existing `RUN_ADAPTERS`, compile hooks, RunSession, BatchRun and LearnedState. City loads that headless host in `workshop/recycling-runtime.html`, an isolated same-origin iframe that never mounts the editor or its storage writers. Both 3D recycling and the retained conveyor use this runner. The browser yields between bounded execution chunks. Additional finite inputs, counters, gates, memory, multiple Models and expanded reusable Bricks keep engine semantics.

City binds anonymous photo feature observations to the marked intake. Answer keys are not present in engine source payloads. Terminal arrivals determine each observation's destination. Conflicting duplicate arrivals, missing terminals, dropped items and unfinished work produce one human check with a reason. The model prediction and per-model trail remain separate from the destination; a correct prediction sent into the wrong bin scores as an incorrect sort.

A City trial freezes its machine and exercise batch while preparing results, then presents those results in the 3D activity. Pause continues the same trial; Reset reads the latest saved machine. Edit in Workshop opens the exact source machine in Recycling. City reports when the saved editable source has newer changes. Revisions remain internal to evidence. Outcomes participate in the existing challenge ledger, which prevents repeat awards.

Publication currently rejects live camera/microphone/pose blocks, room-mode Models, interactive triggers, recurring timers, external-service/output dependencies, unbounded extra feeds, and library Files bindings. Those blocks are identified in validation errors. Students can place a trained library artifact directly on the Model; an isolated City run needs no training-data download. This change does not introduce full graph execution for Driving.

The project envelope already includes arbitrary project sections, so Champion File recovery carries both the editable Workshop workspace and published machine alongside existing economy history. Personal sorting-photo features stay in the project-scoped browser session and are not part of that archive.

Verification lives in `tests/recycling-machine.test.mjs` and the focused `recycling-machine`, `workshop-skills`, `personal-sorter`, `recycling`, and `activity-backup` Playwright suites. Build with `npm run build:city`; run the browser suites with `E2E_DOCROOT='P5 Programme/deploy/city-sim'`.
