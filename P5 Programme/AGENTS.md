# AGENTS.md — Passiona: the P5 AI Champion Programme

The **Passiona project** ("P5 Programme" in this repo) is a Hong Kong school
**AI-literacy programme for P5 (~age 10)**. Kids build a 3D **AI City** and
train an **AI Champion** across ~20 lessons, ending in the "AI City Architect"
capstone. Everything here is a separate project from the repo-root
kindergarten/primary game pipeline in `source/` + `games/` — that pipeline's
rules do NOT apply to this folder.

Live entry point: **https://p5-home.clover-marquis.workers.dev/**

## Golden rules

- **Canonical source of truth: `buddy-kit/client/`.** Any real fix goes there.
- **`deploy/` is build output**, regenerated by `deploy-city-apps.sh`
  (`rm -rf` + `cp` from `buddy-kit/client`). NEVER edit files in `deploy/` for
  real fixes — they get overwritten on the next deploy.
- **No child PII.** Camera/mic data stays in-memory. Everything is client-side.
- **Each app is self-contained** under `buddy-kit/client/<app>/`.
- **Agents decide architecture** — no enforced framework beyond the existing
  buildless ES-module + importmap setup.
- **Library ids must exist in `library.js`** or the item silently skips
  (furniture in templates, props in the picker).
- **Data-loss safety net (Champion File + cloud).** Student work lives in
  localStorage/IndexedDB only — iOS Safari evicts it after ~7 days, so a
  "couple of lessons later" or a different device means it is gone. Every app
  therefore offers **💾 Save my city** (a single bundled Champion File:
  layout + quests + props + skin id + language + progress flags — see
  `city-common/champion-file.js`), and the city-builder adds **☁️ Save to
  cloud / Open from cloud** (KV-backed codes like `NOVA-K7M2P3`, no accounts,
  no PII — worker endpoints `/api/save` + `/api/load`, binding `SAVES`).
  Restore is one tap: upload the file or type the code, then the app reloads
  with everything back. GLBs are never in the Champion File (skins travel by
  preset `id`; a custom Fit-Studio GLB falls back to the preset on a new device).
- **Models must be CC0 / public domain only.** No attribution-required (CC-BY),
  no non-commercial (CC-BY-NC), no unverified "personal-use" itch packs. See
  `library/CC0-MANIFEST.md` — the authoritative keep list. Do NOT add a model
  that isn't free for unrestricted commercial use.
- **The 4 interior scenarios (hospital/lab/spaceship/station) were removed.**
  Their placeholder buttons remain on the hub. Rebuild scenarios later with CC0
  content only; `shared/scenario.js` + helpers still exist and city-builder
  depends on `shared/gltf.js` + `shared/grab.js`.
- **Design quality matters.** Avoid AI-slop (purple gradients, glassmorphism,
  bounce UI, flat type hierarchy). Age-appropriate polish for ~10-year-olds.

## Architecture

- **Buildless ES modules + importmaps.** `index.html` declares the importmap;
  `three` and `three/addons/` resolve to the **vendored** three.js r160 at
  `vendor/three/` (NOT npm).
- **Shared catalog:** `city-common/library.js` exports `LIBRARY` — currently
  ~1420 entries `{ id, name, emoji, glb, category, footprint, height, anchors,
  picker, drivable }`. `picker: false` marks room-only items.
- **Shared scenario framework:** `shared/scenario.js`
  (`mountScenario` → procedural `buildRoomShell` OR `kind:'room'` →
  `setupRoomScene`; proximity-gated 🚪 Enter/Exit via `#zone-toggle`; grab
  system; i18n).
- **GLB loading:** always go through `shared/gltf.js`'s
  `createGLTFLoader()` — it configures BOTH `DRACOLoader` + `MeshoptDecoder`
  (decoders vendored at `vendor/three/addons/libs/draco/gltf/` +
  `meshopt_decoder.module.js`). 70+ Sketchfab GLBs are Draco/Meshopt-compressed
  and silently fail to load without this. **Never** construct a raw
  `GLTFLoader` in new code.
- **Scenario templates:** `spaceship/templates.js`, `station/templates.js`,
  `lab/templates.js`, `hospital/templates.js`. Furniture ids MUST exist in
  `library.js`.

## Tests (run from the repo root)

- **Unit + buddy logic:** `npm run test:unit` (node:test —
  `tests/*.test.mjs` cover metrics, optimizer, road-templates, walkability,
  layout, catalog, meter, action-schema, champion-file round-trip, and the
  worker's `/api/save` + `/api/load` handlers via a fake KV).

  duplicates, orphan report regeneration).

  picker against `buddy-kit/client` via a static server, asserts boot/clean-load
  and picker behaviour. `E2E_DOCROOT=deploy/city-sim` runs the same suite
  against a built bundle (post-minify check).

## Gotchas

- **zsh does NOT word-split unquoted `$VAR` in for-loops** — use `bash -c` or
  export the var into the child shell.
- **Blender** is `/Applications/Blender.app`; `fbx2glb_resilient.py` crashes on
  bare output filenames (`os.makedirs('')`) — always pass full paths.
- **Headless city-builder may stall** before `#prop-toggle` appears (needs a
  city layout to load first) — verify CSS changes by content, not runtime,
  there.
- **Template furniture ids must match `library.js` exactly.**
- **`_p5-reference/P5 Project /`** has a TRAILING SPACE in the folder name —
  quote it or use `$ROOT/_p5-reference/P5 Project /p5-01-recycle-eye`.
- **`sk-modern-kitchen.glb`** is deliberately NOT in the library (conversion
  failed) — skip it.
- **Cars**: `veh_*` drivable cars must be Y-up in the GLB (length along Z,
  height along Y) or they stand vertically in the game. `tools/car-check.html`
  verifies orientation with the game's real loader.
